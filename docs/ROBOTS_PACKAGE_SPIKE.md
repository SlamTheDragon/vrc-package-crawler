# Robots matching package spike (2026-09-27)

**Decision:** adopt exact `@trybyte/robotstxt-parser@2.0.0` for RFC 9309 rule matching in the legacy helper, with focused parity tests and a successful browser-target bundle. Keep HTTP retrieval, failure handling, bounded input, caching, and origin scheduling as explicit application policy. This is a dependency spike and a narrow legacy fix, **not** a completed G3/G5 distributed robots implementation or source access approval.

| Responsibility | Package evidence | Current project state | Next gate |
| --- | --- | --- | --- |
| Rule parsing, user-agent groups, longest matching and percent-encoded paths | [Publisher README](https://github.com/trybyte-app/robotstxt-ts-port) documents a strict `rfc9309` mode, typed match evidence, and repeated-group behavior; [package metadata](https://raw.githubusercontent.com/trybyte-app/robotstxt-ts-port/main/package.json) reports Apache-2.0 and no runtime dependencies | `src/utils/robots.ts` now compiles once per fetched legacy file; package parity tests cover repeated groups, itch `/search`, equal specificity and encoded paths | Expand RFC fixture corpus and compare to authoritative examples before coordinator adoption |
| Fetching and HTTP status | Publisher explicitly says these are outside the package; [RFC 9309 §2.3.1.2](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.2) recommends following at least five redirects, even across hosts, while applying rules to the initial host | Legacy helper still fails closed on redirects because its fetch lacks a pinned cross-origin validator. The local coordinator uses `src/shared/robots_retrieval.ts` to follow up to five HTTPS redirects through pinned transport, bound the body to 512 KiB, reject HTML/partial/invalid UTF-8, and persist the result against the initial origin. `serve` runs a bounded refresh batch on startup and every minute; a narrow compiled live VPM smoke exercised this path. | Test real redirecting hosts when permitted; retain fail-closed behavior when transport or parsing is uncertain |
| File limit and cache | Package does not fetch or cache | Legacy helper caps at 512 KiB, denies when truncated, caches success/missing for 24h and failures for 1h in-process. The coordinator persists bounded snapshots with status, expiry and cross-process refresh leases. | Exercise restart/recovery and source-policy revision behavior; keep malformed and oversized responses fail-closed |
| `Crawl-delay` and rate | [RFC 9309 §2.2.4](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.2.4) leaves extra records outside the standard; the installed parser marks `crawl-delay` unsupported for rule matching | Legacy helper no longer pretends to expose a selected crawl delay; the coordinator uses a separate operator floor | Treat any future source-specific delay as an optional, unambiguous extension that only raises the floor; never let additional nodes multiply origin request rate |
| Source authorization | [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html) says robots rules are not access authorization | `docs/SOURCE_ACCESS_REVIEW.md` remains the separate terms/retention gate | Require approved source profile and robots decision for each claimed URL |

The package is young; adoption is conditional on continued fixture coverage, lockfile pinning, and compiled Bun/Worker parity. Do not use its default Google-compatible mode for project policy: the code explicitly selects `rfc9309`. The installed package has no fetch side effects. Test evidence: `tests/robots_parser_package_spike.test.ts`, `tests/robots_fail_closed.test.ts`, and `bun build --target=browser` produced a 20.33 KB package bundle.
