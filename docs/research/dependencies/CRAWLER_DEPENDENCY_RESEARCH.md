# Crawler-library candidates from `awesome-crawler`

Status: initial research only (2026-09-28). The owner supplied [awesome-crawler](https://github.com/brucedone/awesome-crawler), a cross-language list. It is a discovery index, not evidence that a listed library respects this project's source policies or fits the local coordinator/standalone-node split. No new package has been installed or authorized for live use.

| Candidate | What its own project offers | Fit against this repository | Decision for now |
| --- | --- | --- | --- |
| Existing `cheerio`, `zod`, and `@trybyte/robotstxt-parser` | Already used for HTML extraction, API boundary validation, and RFC-mode robots matching. | Small, separable primitives fit the node/parser and Worker-compatible protocol boundary. Keep testing exact behavior and avoid cloning their functions. | **Keep**; improve adapters and tests rather than inventing another parser/validator. |
| [Crawlee (JS)](https://github.com/apify/crawlee) | TypeScript/Node crawler framework with request queue, storage, scheduling, retries, Cheerio, and optional browser crawling. Its README includes automatic link extraction, proxy/session features, and human-like headers; the [official quick start](https://crawlee.dev/js/docs/quick-start) targets Node. | It could remove substantial single-process crawler plumbing, but its own queue, storage, retry and fetch defaults would compete with coordinator-issued exact-URL leases, cross-node origin pacing, policy review, pinned-DNS egress, and versioned result DTOs. Those behaviors must be proven controllable before substitution. Browser/proxy evasion is not a requested optimization. Worker portability of any chosen subpackage and Bun compiled-binary behavior need a spike. | **Research a narrow adapter/spike**, not wholesale adoption. Measure code removed, bundle size, behavior under cancellation, and whether every request still passes the coordinator policy and safe transport. |
| [node-crawler](https://github.com/bda-research/node-crawler) | Node request queue, Cheerio integration, configurable local `rateLimit`, retries, and duplicate skipping. Its own README documents optional user-agent and proxy rotation. | Local rate limiting cannot be treated as network-wide pacing across VPS/desktop nodes; its request scheduler could issue work outside the coordinator lease. Parser functionality overlaps installed Cheerio. | **Do not replace coordinator scheduling**; only revisit if a bounded, no-autonomous-fetch parsing use case is demonstrated. |
| [Supercrawler](https://github.com/brendonboshell/supercrawler) | Describes custom handlers, robots, rate and concurrency handling. | The features overlap current controls, but an independent per-process robots/rate decision would not meet the shared SQLite coordinator invariants. Maintenance, Bun fit, exact URL override and safe transport require direct tests. | **Research only**; no dependency change. |

The key comparison is *not* “framework versus custom code” in general. A package is attractive when it replaces a domain-neutral primitive without moving source authority from the coordinator to an individual node. The coordinator must continue to decide which exact URL a node may fetch, when, and under which active profile/robots snapshot/lease; the node must validate the versioned API payload, check its lease during egress, and use the pinned public-address HTTPS transport. Any candidate that silently follows links, retries challenges, rotates identity/proxies, or stores raw pages needs a deny-by-default configuration and fixture proof.

Suggested offline spike after the source-profile gate: wrap one candidate's *parser-only or request-execution-only* component around a fake transport for one approved VPM listing fixture. Assert zero unleased requests, no redirects, no auto-enqueue, bounded bytes, cancellation on lost authority, no second per-node rate decision overriding the coordinator, and identical Zod result DTOs. Compare dependency tree and compiled-node/Worker-target bundle sizes against the current implementation. If it cannot meet those invariants without more glue than it removes, retain the existing narrow primitives.
