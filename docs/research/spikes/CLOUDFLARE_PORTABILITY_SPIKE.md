# Cloudflare portability spike (2026-09-27)

No Cloudflare account, deployment, or remote database is used by this milestone. This is a capacity check against current official documentation, not a hosting decision or cost estimate for an unmeasured workload.

| Constraint | Current local slice | Implication before deployment |
| --- | --- | --- |
| Worker bundle | `bun run build:worker` produces a 190.86 KB browser-target `handler.js` from the portable `Request → Response` core | Build success does not prove Cloudflare runtime compatibility. A Wrangler local runtime test and deployed staging test remain necessary. The current [Workers size/memory/CPU limits](https://developers.cloudflare.com/workers/platform/limits/) are 64 MiB script size, 128 MB memory, and 10 ms CPU per HTTP request on Free; paid CPU defaults to 30 seconds and can be configured higher. Profile validation cost before choosing a tier. |
| Request body | The node API rejects payloads above 256 KiB | This is well below Cloudflare's [100 MB Free-plan request body cap](https://developers.cloudflare.com/workers/platform/limits/), but intentionally prevents raw-page archival via the node result route. |
| D1 catalog | Local source versions/events are SQLite rows; no public catalog bridge yet | A Free-plan D1 database is currently capped at 500 MB and 50 queries per Worker invocation; paid databases at 10 GB and 1,000 queries per invocation. Rows have a 2 MB maximum. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) make bounded/batched catalog reads and retention decisions prerequisites. The current local claim loop may inspect up to 100 candidates and must not be copied into a D1 Worker without query-budget measurement. |
| Origin lease coordination | `LocalCoordinatorStore` uses one transactional SQLite file and an origin lease row | Per-origin distributed serialization needs a consistency model, not just an HTTP handler port. SQLite-backed Durable Objects have per-object storage and CPU constraints and single-object serialization; [Durable Object limits](https://developers.cloudflare.com/durable-objects/platform/limits/) should be measured with the real job rate. Mapping each origin to one Durable Object is a hypothesis, not an accepted design. |
| Cost | No observed request, row-read/write, stored-byte, or CPU distributions yet | Do not extrapolate a bill from prototype DB size. Capture local metrics first, then apply the current [Workers/D1/Durable Objects pricing](https://developers.cloudflare.com/workers/platform/pricing/) before account setup. |

The user-selected local path remains authoritative. `src/worker/handler.ts` has no Bun/Node imports; `src/worker/local_sqlite.ts` and `src/worker/local_main.ts` are intentionally local adapters. A Cloudflare storage adapter, Wrangler simulation, and staging deployment are not implemented and must not be inferred from the browser bundle check.
