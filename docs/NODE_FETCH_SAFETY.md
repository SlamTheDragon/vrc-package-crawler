# Standalone node metadata transport (2026-09-27)

The coordinator may assign a URL to a node running on a desktop or VPS. That turns the node into a potential server-side request forgery (SSRF) target if a bad job reaches it. This checkpoint applies [OWASP's SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html): constrain protocol and redirects, inspect every resolved A/AAAA address for non-public destinations, and avoid the validation/request DNS gap. [Node's DNS `all` option](https://nodejs.org/api/dns.html) exposes all addresses returned by the operating-system resolver; [`https.request` with `servername`](https://nodejs.org/api/https.html) lets the node connect to a checked IP while retaining TLS hostname verification and SNI.

| Boundary | Current behavior | Proof / limit |
| --- | --- | --- |
| Operator seed | Rejects HTTP, credentials, fragments, non-443 ports, localhost, trailing-dot hostname aliases, and private/reserved IP literals. GitHub jobs must use the public REST repository metadata endpoint; a different capability cannot use `api.github.com` to bypass its pacing floor. | Local protocol tests. A hostname can still resolve differently later; seed validation is only the first layer. |
| Node fetch | Resolves the hostname, rejects an empty answer or any private/reserved address, rejects trailing-dot aliases, connects to one checked IP through HTTPS with the original hostname in Host/SNI, and does not follow redirects. A 3xx result is blocked pending source review rather than retried indefinitely. | `src/node/public_metadata_fetch.ts`, adapter tests, and compiled metadata-only fetches of VRChat Community's example listing/recipe and a public GitHub repository API record. No release archive requested. |
| Payload | Checks declared length and streamed bytes against 2 MB, requests identity encoding, and passes a bounded response to the existing parser. Unsafe destinations become a blocked result rather than repeated retries. | Unit tests cover oversized declared length and a chunked response without `Content-Length`; live checks cover successful TLS and schema ingestion. A real-socket streaming integration test remains open. |
| Coordinator credential | HTTP is accepted only on loopback; remote coordinator URLs must use HTTPS. | Client constructor test and compiled loopback smoke. Remote TLS deployment has not been run. |
| Active lease authority | A fetching heartbeat carries the exact job and lease IDs. The node checks again every five seconds and immediately before submitting; a rejected or unreachable coordinator aborts the active metadata request and prevents result submission. | `tests/node_lease_runner.test.ts` covers coordinator loss and loopback operator suppression during a pending fetch. The compiled VPM smoke exercises the new heartbeat schema on successful real requests. Cancellation is bounded by heartbeat interval plus its five-second request timeout; it is not instantaneous or a creator-wide delisting system. |

The `src/shared/ip_policy.ts` classifier is extracted from the existing legacy server implementation and remains a conservative local rule, not a universal proof that every public address is safe. The node checks cancellation both before and after DNS resolution so a lost lease cannot initiate a socket after a delayed lookup. A future source-access profile should add per-origin allowlists, explicit port policy, and DNS/network egress controls. The legacy server proof path still checks one OS-resolved address rather than every answer; its transport is not automatically equivalent to the node's. Hosts with legitimate non-443 HTTPS are deferred until source-specific review. This safety gate does not itself authorize crawling a site's content or retaining it.
