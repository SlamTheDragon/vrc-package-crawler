# Source Access and Fetch Safety

> **Status:** Consolidated source-access architecture, node transport safety, and platform access review records.
> Date of consolidation: 2026-09-30.

## 1. Standalone Node Fetch Safety and Transport Controls

The coordinator can assign a URL to a crawler node on a desktop or VPS. That makes the node a potential target for server-side request forgery (SSRF). This checkpoint follows [OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html):
- Constrain protocol and redirects.
- Check every resolved A/AAAA address for non-public destinations.
- Eliminate the DNS validation-request gap.

[Node DNS `all` option](https://nodejs.org/api/dns.html) returns all addresses from the system resolver. [`https.request` with `servername`](https://nodejs.org/api/https.html) connects to a checked IP while keeping TLS hostname verification and SNI.

### Transport Boundaries

| Boundary | Current behavior | Proof and limits |
| --- | --- | --- |
| Operator seed | Rejects HTTP, credentials, fragments, non-443 ports, localhost, trailing-dot hostname aliases, and private/reserved IP literals. GitHub jobs must use the public REST repository metadata endpoint. Other capabilities cannot use `api.github.com` to bypass its pacing floor. | Local protocol tests. A hostname can still resolve differently later. Seed validation is only the first layer. |
| Node fetch | Resolves the hostname. Rejects an empty answer or any private/reserved address. Rejects trailing-dot aliases. Connects to one checked IP through HTTPS with the original hostname in Host/SNI. Does not follow redirects. A 3xx result is blocked pending source review rather than retried indefinitely. | `src-crawler/src/node/public_metadata_fetch.ts`, adapter tests, and compiled metadata-only fetches of VRChat Community example listing/recipe and a public GitHub repository API record. No release archive requested. |
| Payload | Checks declared length and streamed bytes against 2 MB. Requests identity encoding. Passes a bounded response to the parser. Unsafe destinations become a blocked result rather than repeated retries. | Unit tests cover oversized declared length and a chunked response without `Content-Length`. Live checks cover TLS and schema ingestion. A real-socket streaming integration test remains open. |
| Coordinator credential | HTTP is accepted only on loopback. Remote coordinator URLs must use HTTPS. | Client constructor test and compiled loopback smoke. Remote TLS deployment has not run. |
| Active lease authority | A fetching heartbeat carries exact job and lease IDs. The node checks every five seconds and right before submitting. A rejected or unreachable coordinator aborts active metadata requests and stops result submission. | `src-crawler/tests/node_lease_runner.test.ts` covers coordinator loss and loopback operator suppression during a pending fetch. Compiled VPM smoke exercises heartbeat schema on real requests. Cancellation is bounded by heartbeat interval plus five-second request timeout. |

The `src-crawler/src/shared/ip_policy.ts` classifier is extracted from the legacy server. It remains a conservative local rule, not universal proof that every public address is safe. The node checks cancellation both before and after DNS resolution so a lost lease cannot start a socket after a delayed lookup. A future source-access profile must add per-origin allowlists, explicit port policy, and DNS egress controls. The legacy server proof path checks one OS-resolved address rather than every answer; its transport is not equivalent to the node. Hosts with non-443 HTTPS are deferred until source review. This safety gate does not authorize crawling or retaining content.

## 2. Source-Access Gate Architecture and Policy Design

Status: **Owner chose separate source-access profiles; local coordinator gate partially implemented** (2026-09-28). This document does not approve a source, select a capability, or authorize a live fetch. It describes the gate between a queued job and a network request. An eighth, lead-only Shopify capability was added separately after the original seven-capability baseline. The same profile gate applies to it. This is an engineering control proposal, not legal advice. A source-specific review must determine usable endpoints and retained/published representations. Source-by-source evidence is recorded in [Section 3](#3-platform-source-access-review-and-ingestion-limits).

The shared DTO and exact-origin/path/purpose matcher live in `src-crawler/src/shared/source_access_profile.ts`. The local SQLite store has zero default grants and authenticated, audited create/list/disable routes. Automatic and explicit robots refresh require a due job matching an active profile. Claim binds that profile to the lease and applies its rate floor. Fetching heartbeat and new result submission recheck the bound profile. Disabling a profile clears its active leases. The node receives retained classes and omits unapproved creator prose. The coordinator rejects unauthorized prose or normalized evidence independently. New versions, events, issues, and leads record the approving profile ID. Offline fixtures and compiled local smokes cover the narrow boundary. This is **not full source-policy conformance**: source approval and retention research, older DB migration, transitional direct driver paths, full objection/delisting, and public publication filters remain open.

### The Owner Decision and Considered Alternatives

**Owner decision:** Every job, manual and auto-queued, must match a separate, active, scoped source-access profile before a live fetch lease. A seed queues a request; it is not approval. A matching auto-queue rule permits lead-to-job promotion, not network access. The local coordinator enforces the fetch boundary. Evidence and publication policy are not complete.

| Position | Technical meaning | Advantage | Failure mode unless constrained | Owner status |
| --- | --- | --- | --- | --- |
| A. Structured seed is approval | Replace bare `seed <platform> <url>` with an auditable, expiring per-URL approval record containing reviewed request and retention scope. Repeat fetches stay bounded by that record. Auto-queued jobs need equivalent reviewed source authorization, not merely an auto-queue rule. | Smallest approval scope. One-off metadata smokes remain easy to explain. | A bare seed or URL cannot express allowed methods, cadence, retention, publication, expiry, or revocation. Treating bare seeds as approval preserves the gap. Many seeds could become an unreviewable policy inventory. | **Not chosen for this milestone** |
| B. Separate source profile for both routes | Operator creates a profile scoped to platform, canonical origin, exact/path-prefix endpoint, and purpose. Manual and auto-queued jobs match it before refresh and claim. A job still needs fresh robots, pacing, and a node lease. | One auditable policy covers repeated jobs and both promotion paths. Revocation has source-wide semantics. | A broad profile could over-authorize if path, query, method, representation, expiry, or host matching is loose. Profile existence is an operator judgment, not a legal finding. | **Chosen: local fetch gate implemented, broader policy incomplete** |
| C. Bare seed/auto-queue rule is approval | Keep legacy behavior and treat job/rule creation as sufficient. | No implementation cost. | Records omit terms/endpoint and field-level retention decisions. Manual and auto jobs have inconsistent stop scopes. This does not meet the G3/G5 source-profile gate. | **Not recommended; not accepted** |

The decided boundary is **approval granularity**. A seed is a request to queue work, not an approval. This does not make a community-directory lead authoritative product evidence.

[RFC 9309 §1](https://www.rfc-editor.org/rfc/rfc9309.html#section-1) states robots rules are not access authorization. Handling of unreachable robots results is defined in [RFC 9309 §2.3.1](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1). The gate above is an additional project policy, not a reinterpretation of robots. Cloudflare Queues has [at-least-once delivery](https://developers.cloudflare.com/queues/reference/delivery-guarantees/). Any queue delivery still needs coordinator-side idempotency and policy re-evaluation at claim and submit. No Queue product is required for the local design.

### Candidate Policy Object and Evaluation

The current schema has a stable `profile_id`, platform, exact canonical origin, exact or slash-terminated path, optional exact ASCII query, fixed GET, purpose (`discovery`/`metadata`), expiry, delay floor, review reference/reason, retain/publish class arrays, creation/disable timestamps, and audit actor. Canonical percent-encoded UTF-8 paths are allowed only as exact scopes. Encoded ASCII and encoded directory scopes are rejected. This distinction follows [WHATWG URL Standard path and percent-encoding rules](https://url.spec.whatwg.org/). But remote servers can normalize URLs differently. Source review must check that. It does not yet model immutable revisions, source role, review evidence digest, general query policy, request budget, or retention duration.

| Field | Purpose and guard |
| --- | --- |
| `profile_id`, immutable `revision`, `state` (`draft`, `active`, `disabled`, `expired`), `created_at`, `expires_at`, `disabled_at` | Stable audit identity. Updates create revisions without in-place silent widening. Active validity uses coordinator time. |
| `platform`, `source_role` (`first_party_product`, `first_party_metadata`, `discovery_only`), canonical `https` `origin` | Prevent community indexes, VPM hosts, GitHub API, and seller storefronts from inheriting approval from one another. Role is explicit and origin equality is exact. |
| `path_scope` (exact or slash-terminated prefix), `allowed_methods` (currently `GET`), explicit query policy, endpoint class | Match the network target, not just a host. Reject path normalization ambiguities, credential-bearing URLs, ports, fragments, and noncanonical encodings. A prefix must respect directory boundaries. Query URLs require an explicit rule. |
| `purpose`, `review_reference`, `reviewed_at`, `reviewer`, `reason`, `evidence_digest_or_link` | Record which endpoint, terms, and rate assessment an operator relied on. A review reference is evidence provenance, not proof of permission. |
| `min_delay_ms`, concurrency/budget, retry/objection/challenge stop conditions | Combine with origin pacing by taking the stricter effective floor. A 429, challenge, or objection must not be retried simply because the profile remains active. |
| `accept_classes`, `retain_classes`, `publish_classes`, `retention_until_or_policy_id` | Distinguish transient response, normalized facts, creator prose, raw JSON, URL, image derivative, historical versions, and public projection. Absence is deny. Version these decisions independently of fetch approval if needed. |

Evaluator input is `(platform, GET, canonical URL, purpose, now, active profile, suppression/objection state, robots snapshot, origin pace)`. A job can be **queued** before access approval. But a **claim** is granted only when each required predicate is satisfied. The lease binds a profile ID and new evidence records it. Overlapping active profiles for the same platform, origin, and purpose are rejected for now. This avoids fallback to a broader profile after disable. A later revision model must preserve that rule. A deny or stop record overrides all allows.

A source profile must not be confused with a VPM `lead_autoqueue_rules` row. That rule answers whether a lead can become a job without operator intervention. The access profile answers whether a job can cause a network request and what can be retained or published. Both can expire or be disabled independently. Unknown lead kinds stay pending review.

### Transition Plan for Separate-Profile Boundary

1. **Partly done:** Strict operator payload and authenticated create/list/disable routes plus local CLI exist. Add inspect/revision workflow, reviewer identity beyond one token, evidence digest verification, and durable history. Node credentials never administer profiles.
2. **Partly done:** SQLite profile tables, nullable old-job `lease_profile_id`, purpose, and evidence profile IDs exist with zero synthesized grants. Older-schema tests prove pre-policy leases clear on upgrade and unbound leases cannot continue or submit. The prototype `bin/crawler_state.db` remains read-only test evidence.
3. **Partly done:** One exact URL matcher is reused for refresh eligibility, claim, and bound lease checks. Robots, claim, heartbeat, and submit recheck their predicates. Strict transport controls remain enforced. Exact-query and UTF-8 path extensions have offline BOOTH browse fixtures. The lease carries purpose. The BOOTH node adapter extracts bounded candidate leads from category paths. The coordinator rejects product observations and off-site leads from browse jobs.
4. Keep discovery reports as provenance-bearing pending leads. Fetch a source-approved discovery index only within its reviewed role. Outbound links do not transfer authorization to destinations. Approving a lead to become a job and approving destination access are separate actions.
5. **Partly done:** Normalized facts and creator prose are checked at submission. The node minimizes prose by lease policy. Add a profile-aware publication projector and retention duration/removal. If policy changes later, suppress public projection without rewriting raw observations. Resolve pre-policy historical rows before export.
6. Opt-in live smoke scripts require an explicit review reference and retained-class selection. They create short-lived exact-path profiles and retain no public classes. Revised GitHub and two-origin VPM template smokes passed through the gate on 2026-09-28. Regression retests passed after robots preflight joined origin pacing. Keep selectable capabilities enabled by default while unapproved sources have zero eligible fetch leases.

## 3. Platform Source Access Review and Ingestion Limits

This is an engineering gate record, not legal advice. Driver selection is distinct from authorization to issue live requests or retain/publish material. The node defaults to all selectable capabilities. But a seed only queues a job. An active scoped source profile and robots allow are required before refresh or lease. Revised GitHub and VPM template smokes passed on 2026-09-28 with exact-path profiles, normalized-facts-only retention, and no publication classes. No sustained source crawl has run.

The intended flow is discovery-driven: nodes execute assigned tasks and report provenance-bearing leads. The coordinator decides which leads become eligible jobs and controls leases, pacing, and stop rules. The current operator-seeded slice is a bootstrap. Every manual and auto-queued job requires a separate scoped profile. An eighth `shopify` capability supports only offline-verified product-sitemap lead extraction; no live Shopify merchant is approved.

**Current enforcement boundary and gaps:** The local coordinator requires an active scoped profile before robots refresh, lease claim, fetching heartbeat, and new submission. `seed` and VPM auto-queue rules create or promote jobs, but do not grant fetch access. The profile captures reviewed endpoint, purpose, cadence, expiry, and retention/publication classes. Creating a profile is an operator judgment, not a legal finding. Transitional direct drivers, review evidence, historical projection, retention duration, and delisting lack full end-to-end enforcement. Robots allowance alone never grants permission.

The owner also selected **hybrid lead review**: reviewed source rules can auto-queue matching leads. Unfamiliar leads remain pending. The operator API supports authenticated, audited manual VPM-listing review, scoped expiring VPM-listing auto-queue rules, and profile create/list/disable. It does not promote other leads yet. Disabling a rule stops future and in-flight rule-backed fetches. It does not remove already retained evidence or separately seeded jobs. Disabling a profile stops new leases in its scope and invalidates active leases. It does not remove retained historical data. See [operator control API](OPERATOR_CONTROL_API.md).

### Bounded Engineering Scopes

#### GitHub One-Request Engineering Scope (2026-09-28)
Review reference `docs/scratch/decisions/current/SOURCE_ACCESS_AND_SAFETY.md#github-one-request-engineering-scope-2026-09-28` applies **only** to an opt-in local test of `GET https://api.github.com/repos/vrc-get/vrc-get`. It includes no authentication, search, README, release, archive, or follow-on requests. GitHub [Get a repository reference](https://docs.github.com/en/rest/repos/repos?apiVersion=2026-03-10#get-a-repository) states public resources can be requested without authentication. Its [API version reference](https://docs.github.com/en/rest/about-the-rest-api/api-versions) lists `2026-03-10`. Its [rate-limit reference](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) gives 60 unauthenticated requests/hour per source IP with response headers as authoritative. The script single metadata request, 60-second origin floor, bounded observation, `normalized_facts` retention, and empty publication classes are the engineering limits. Runtime robots and response status remain decisive. This is not a legal opinion, permission for broad repository harvesting, or approval to publish descriptions. If the runtime returns a denial, challenge, or rate limit, stop without retrying automatically.

Outcome: Default sandbox could not connect for robots (`ECONNREFUSED`), so it made no product request. The test passed when run with network access: robots preflight succeeded, one compiled standalone node returned `changed`, and the coordinator persisted `github:590790034` with the source link. The later pacing regression retest passed, including profile attribution and prose minimization assertions. The script removed temporary databases. This proves bounded local profile-gated requests, not a sustained crawl or permission finding.

#### VPM Two-Template Engineering Scope (2026-09-28)
Review reference `docs/scratch/decisions/current/SOURCE_ACCESS_AND_SAFETY.md#vpm-two-template-engineering-scope-2026-09-28` applies only to one opt-in local test of two exact GET URLs: `https://vrchat-community.github.io/template-package/index.json` and `https://raw.githubusercontent.com/vrchat-community/template-package-listing/main/source.json`. VRChat [VPM repository format](https://vcc.docs.vrchat.com/vpm/repos/) and [listing guide](https://vcc.docs.vrchat.com/guides/create-listing/) document public JSON listings consumed by VPM clients, but do not grant broad collection or redistribution rights. Outcome: The compiled smoke passed. The coordinator recorded `com.vrchat.demo-template` release `0.0.7` with a ZIP hash as metadata, but fetched no ZIP. ### Jinxxy Policy Interpretation Boundary

The API clause is not limited to storefront editing: §23.2 states *all automated access* must use the official API unless written permission is obtained. Section 8.2 separately addresses automated systems and systematic retrieval for directories. The API Jinxxy documents is the Creator API, with dashboard credentials and store-specific products, customers, licenses, and orders. We found no first-party documentation for a public cross-creator catalog endpoint. Absence of documentation is not proof that no endpoint exists. The public marketplace and sitemap show discoverability by a human browser, not an exception for this automated index. The question for Jinxxy is how it intends third-party public catalog discovery to work. This is a first-party policy interpretation to confirm, not a technical inference to settle by inspecting undocumented browser calls.

### Robots Implementation Checkpoint

The legacy worker checks queued URLs, but direct driver fetches are not all mediated by the coordinator. Its shared helper fails closed on network failures fetching `robots.txt`, matching [RFC 9309 §2.3.1.4](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.4). The [parser package spike](../../../research/SPIKES.md) replaces handwritten legacy rule matching and tests repeated groups and encoded paths. The local coordinator persists bounded per-origin robots snapshots, withholds claims until fresh snapshots exist, checks exact URLs using the strict parser, and rejects submissions when policy disallows them. Trusted refresh follows up to five HTTPS redirects with fresh DNS checks per hop. Rules stay attached to the initial origin. Both explicit and queued robots refresh require a due job matching an active source profile. An unapproved seed cannot trigger automatic robots egress. SQLite refresh leases coordinate processes, and `serve` runs bounded passes on startup and every minute. Fixture and two-process checks passed. Exact-path GitHub and two-origin VPM smokes passed through this gate. Standalone metadata requests abort after a lease-bound heartbeat fails. This is bounded polling, not instantaneous source-wide stop. Centralization remains partial: source-specific terms, legacy direct-fetch coverage, historical publication handling, and creator-wide cancellation remain open. The shared itch `/search` guard at legacy browse, seed, and node fetch boundaries is a narrow known-path stop, not a substitute for those tasks.
