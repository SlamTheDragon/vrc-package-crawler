its default is `metadata`; a typed command remains a usability improvement.

The plain-language vocabulary, flow, and code ownership for ACCESS-02,
ACCESS-06, ACCESS-07, and SOURCES-01 are now in
[PIPELINE_RESPONSIBILITY_MAP.md](current/PIPELINE_RESPONSIBILITY_MAP.md). Robots
preflight is a coordinator step after a profile-eligible queued job and
before a content lease. A source profile controls *whether and how a node
may fetch*; a source role would express *how authoritative the result is* and
is not yet implemented. A narrow exact-query/canonical UTF-8 path matcher
now supports offline BOOTH browse fixtures, but broader query policy and
individual source approvals stay open. The owner has not yet been asked to approve a specific unprofiled
robots exception after seeing this map.

IDENTITY-01 is a design proposal: unresolved possible front relationships
may be exposed to downstream applications for optional user feedback, then
evaluated as steering signals without automatic model training or automatic
merges. It needs schema, abuse/consent, retention, and legal review before
implementation or a statement of rights in `LEGAL.md`.

DEPENDENCY-01 is clarified: the crawler collection is inspiration for
research into individual maintained packages that remove duplicate local
machinery, not approval to replace the coordinator with a framework.

ACCESS-03 remains open. The owner-provided external writing-skill locations
were not readable from this workspace; no content from them has been assumed.

## Task Queue: Strongly Typed Item Migration (PKG-01)

- **Objective:** Branch out strongly typed items, schemas, and contracts from `src-crawler/src/shared/` into the dedicated `src-package` (`vrc-packages-api`) package.
- **Trigger Precondition:** Coordinator, Node, and Operator API contracts and connections must be fully stabilized and verified end-to-end in pre-production mode.
- **Items to Branch Out:**
  1. `node_protocol.ts`: Protocol version, Claim, Heartbeat, Job, Observation, DiscoveryLead, Result schemas.
  2. `operator_protocol.ts`: Lead review, auto-queue rules, source-access profiles, catalog projection schemas, and keyset cursors.
  3. `evidence_class.ts`: Evidence class definitions and validation.
  4. `vpm_version.ts`: Canonical SemVer 2.0.0 validation and parsing.
  5. `source_targets.ts`: Standardized platform identity matchers (BOOTH, GitHub, Shopify sitemap).
  6. `access_outcome.ts`: Access failure classification and retry-after header parsing.
  7. Typed API Client: Fetch-based SDK client wrapper for downstream consumers (`src-web`, CLI, scripts).
- **Package Target:** `src-package/` (`vrc-packages-api`), exporting ES modules and TypeScript definitions.
- **Consumers:**
  - `src-crawler`: Coordinator and node binaries import protocol types from workspace package `vrc-packages-api`.
  - `src-web`: SvelteKit frontend dashboard imports catalog, node, and operator API client types.

## Operational Guidelines for Queue Triage

1. **Safety First**: Any feature touching outbound network requests must have fail-closed defaults.
2. **Provenance Preservation**: Retain upstream URL, origin timestamps, and raw hashes without synthesizing missing metadata.
3. **No Legacy Burden**: The project is version 0 pre-production. Do not retain backwards-compatibility hacks for retired Phase 1–4 binaries.
