# Asset indexing safeguards

Reviewed 2026-10-03. This note replaces a historical essay that mixed project safeguards with unsupported legal conclusions. Use the [legal library](03_legal_jurisprudence_and_governance.md) and [platform matrix](PLATFORM-MATRIX.md) for source-specific review. No permission follows from this note.

| Operation | Project boundary | Check before publishing a promise |
| --- | --- | --- |
| Discovery | Community indexes and credited authors are leads toward publisher-controlled fronts | Preserve explicit link chains. Do not import third-party tags, prices or ownership claims as canonical facts. |
| Metadata requests | Coordinator-directed, scoped, leased requests only | Active source profile, real robots evidence, shared origin budget, bounded response and safe transport. |
| Product files | No executable, archive or model downloads | Reject binary URLs and content through all adapters and redirects; a listed release URL remains metadata. |
| Creator prose | Access does not imply retention or publication rights | Review exact fields and approved classes. Bound snippets; do not call a fixed character count a legal safe harbor. |
| Images and video | Media pointers, thumbnails and caching require separate scope | Prototype BLOB services are not current capabilities. Hotlinking or thumbnails are not universally lawful. No new image-fetch path follows from this research. |
| Attribution | Link consumers to supported publisher/front evidence | Distinguish creator, merchant, reseller and directory. Avoid endorsement or ownership claims from branding alone. |
| Removal | Intake must not permit an unrelated caller to suppress another creator | Verify authority, separate pending requests from action, revoke fetches and publication consistently, and test downstream tombstones. |
| Data protection | Public creator information and free-text input can identify people | Inventory stored fields, purposes, access, retention, export and deletion. Anonymous endpoints are not proof of anonymous data. |

## Operational precautions

Use an identifiable bot and a contact route. Stop on authentication barriers, challenges and source objections rather than rotating identities or evading controls. Request a documented interface or permission where needed.

Set pacing from reviewed source limits and observed conditions, not a universal one-request-per-second claim. Extra nodes must not increase the origin budget. Keep source access, robots matching and lease authority independent.

Keep model-training uses outside the current metadata-discovery scope. Review actual platform and creator licenses before making broad statements about community-wide prohibitions.

## Corrections and retained intent

The previous blanket BOOTH ban, blanket Gumroad ban, token requirement for all GitHub metadata, thumbnail-safe-harbor assertions, directory-size figures and universal legal deadlines are withdrawn. FANBOX policies do not establish BOOTH rules. Public facts do not automatically clear contractual extraction or personal-data processing.

Retained intent: metadata discovery, canonical outbound attribution, no product binaries, bounded retention, source objections and creator-controlled removal. These remain requirements to verify, not proof that current code enforces them.

For prototype versus current paths, use the [parity audit](PROTOTYPE_PARITY.md). Current implementation risks and ambiguous media/removal decisions are in the [critical ledger](IMPLEMENTATION_PLAN.md).
